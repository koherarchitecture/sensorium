## Smoke test — primary verification of the v0.1.3 lib.rs fix

The flatpak smoke test on this VM is the **primary** verification that the v0.1.3 lib.rs fix (carried over from v0.1.3 hotfix source) works on a user machine. Two reasons:

1. The Parallels arm64 VM is not the build machine — `env!("CARGO_MANIFEST_DIR")` baked into the binary at build time on this VM points at the VM's own filesystem path. Whether that path coincides with the source-tree location on a user's machine is irrelevant — what matters is whether the bundle-resource path resolves correctly inside an installed bundle.
2. The flatpak sandbox is the cleanroom: the sandboxed binary cannot see the host's source-tree paths even if they exist, so the compile-time-manifest fallback (path 4 inside `flavour::load_flavour`) cannot fire. Only the proper user-data + bundle-resource paths are available — which is exactly the user-machine condition.

```bash
# Clear any prior install + user-data to force fresh first-run state.
flatpak uninstall --user app.koher.sensorium -y 2>/dev/null
rm -rf ~/.var/app/com.koher.sensorium/

# Install the freshly-built bundle.
flatpak install --user --bundle releases/linux-arm64/sensorium-0.1.3-arm64.flatpak -y

# Launch.
flatpak run app.koher.sensorium &
sleep 5
```

## Failure modes

- **`./node_modules/.bin/tauri: not found` after npm install** — the cli-linux-arm64-gnu binding didn't install. Inspect with `ls node_modules/@tauri-apps/`. If only `cli-darwin-*` is there, npm's optional-dependencies bug bit again — rerun `rm -rf node_modules package-lock.json && npm install`.
- **`bash scripts/build-flatpak.sh` fails with `unsupported ARCH 'aarch64'`** — the case statement in the script wasn't updated to include both Debian and Linux kernel arch strings. Should not happen with the current script (it uses `dpkg --print-architecture` which returns `arm64`, not `aarch64`). If it does, override with `ARCH=arm64 bash scripts/build-flatpak.sh`.
- **flatpak-builder stalls or fails on a runtime download** — re-confirm `flatpak list --user --runtime` shows both `org.gnome.Platform//49` and `org.gnome.Sdk//49`. If missing, install per `V0.1.2-ARM64-PREREQ.md`.
- **Smoke-test calibration fails with "no flavour loaded"** — the lib.rs fix is not in the built binary. Confirm `git log --oneline -5` shows the v0.1.3 / v0.1.3 commits that include the lib.rs change. If they're absent, the branch wasn't aligned correctly — re-run step 2 and confirm `grep "setup: loaded flavour" src-tauri/src/lib.rs` returns a line (that's the success log message in the new code). If the line is present but smoke test still fails, there's a deeper issue — capture full Sensorium logs (`flatpak run --command=cat app.koher.sensorium /tmp/sensorium.log` if logging-to-file is on, or run `flatpak run app.koher.sensorium` from a terminal to see stdout/stderr) and report.
- **Out of disk** — `src-tauri/target/` Rust build cache and `.flatpak-builder/` can be large; if disk is tight, the cleanup at step 2 helps. The Rust dependency cache rebuild adds ~5-10 minutes but is a one-time cost.
