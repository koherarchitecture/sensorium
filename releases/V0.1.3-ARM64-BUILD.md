# V0.1.3-ARM64-BUILD — build the arm64 .deb and arm64 .flatpak

For the Claude Code session running on the **arm64 Parallels VM** (Apple Silicon Linux). Builds the v0.1.3 arm64 artefacts and stages them in `releases/linux-arm64/`. **Build only — no release.**

The Mac DMGs are already built and committed locally on the shared filesystem (`e13a75f release(macos): sensorium 0.1.3 aarch64 .dmg + x64 .dmg`, 21 May 2026 evening). The Linux x86_64 box's amd64 `.deb` + `.flatpak` are also tracked locally on Mac (`c64363c release(linux-amd64): …`, a parallel mirror of Linux's local-only `8f97789` — byte-identical artefacts). Once the arm64 build lands as the next commit, all six v0.1.3 artefacts are tracked on the shared Mac+VM `v0.1.3` branch and ready for the GitHub release — gated on explicit user "release" / "ship" instruction.

**Context for v0.1.3:** Release combining three calibration-load fixes (lib.rs setup-callback + flavour.rs `_up_/` path + flatpak manifest copy) + JS defence-in-depth seed + install-flavour button notice + suggested-tone cues feature. Substance: (a) `src-tauri/src/lib.rs` moves flavour seed-and-load into the setup callback with real paths via `handle.path()`; (b) `src-tauri/src/flavour.rs` checks `_up_/flavours/` first in both `load_flavour` and `ensure_flavour_in_user_data`; (c) `packaging/flatpak/app.koher.sensorium.yml` adds `mkdir -p /app/lib && cp -r deb-payload/usr/lib/sensorium /app/lib/sensorium` so the bundled lib tree actually reaches the flatpak; (d) `src/js/first-run.js` adds defence-in-depth wizard-time seed; (e) `src/js/settings-modal.js` wires the three dead install-flavour buttons to an inline notice; (f) suggested-tone cues above the composer — non-interactive, 5-candidate vocabulary, derivation in `src-tauri/src/rules/tone_suggestions.rs`. **The amd64 flatpak smoke test on the x86_64 Linux dev box already passed (21 May 2026 afternoon)** — startup tracing line `setup: loaded flavour 'sycophancy' v0.1` confirmed the resource lookup works in a sandboxed installed build. This arm64 build is a structurally-identical belt-and-braces confirmation; the lib.rs + flavour.rs + flatpak-manifest fixes are platform-independent.

## ⚠️ Critical context — shared filesystem with Mac

The repo lives at **`/media/psf/Dropbox/personal_projects/koher/tools-release/sensorium/`** (Parallels Shared Folder mount). This path is the **same filesystem** as the Mac's `~/Dropbox/personal_projects/koher/tools-release/sensorium/` — the VM does not have its own copy. That means:

- **`.git/` is shared.** Any commit on the VM advances the shared `v0.1.3` branch; Mac sees it instantly. There is no separate "VM-local" history.
- **`releases/` is shared.** The Mac's DMGs (`releases/macos-aarch64/sensorium_0.1.3_aarch64.dmg`, `releases/macos-x64/sensorium_0.1.3_x64.dmg`) and the Linux x86_64 box's amd64 artefacts (`releases/linux-amd64/sensorium_0.1.3_amd64.deb`, `releases/linux-amd64/sensorium-0.1.3-amd64.flatpak`) are visible to the VM and must be preserved through this session.
- **`node_modules/` is shared.** When this runbook runs `npm install` it will overwrite the Mac's darwin Tauri CLI bindings with Linux ones. After this session, the Mac must re-run `rm -rf node_modules package-lock.json && npm install` before its next build. This is a known cross-platform trap.

**Two destructive commands from the original v0.1.2 era runbook have been removed for this v0.1.3 build:**

- ~~`git reset --hard origin/v0.1.3`~~ — would erase Mac's local artefact commits (`c64363c`, `e13a75f`) from the shared branch.
- ~~`git clean -fd`~~ — would wipe the staged Mac DMGs and Linux amd64 artefacts from the shared filesystem.

Do not reintroduce them. If reconciliation is needed for some unexpected drift, stop and report — don't reset.

## Steps

```bash
# 1. Confirm host.
uname -s -m
# expect: Linux aarch64

# 2. Move to the repo and confirm starting state. DO NOT reset or clean.
cd /media/psf/Dropbox/personal_projects/koher/tools-release/sensorium
pkill -f tauri 2>/dev/null
pkill -f flatpak-builder 2>/dev/null

# Branch + history sanity check.
git branch --show-current
git log --oneline -8
# expect: branch v0.1.3. History should include (top-down, possibly with extra
# docs commits above) c64363c (Mac-side amd64 mirror), e13a75f (Mac macos),
# dbfee0b (origin docs), d835413 (origin source), b297c6f (v0.1.2 arm64),
# 1c3cf0e (v0.1.2 macos). Quick check:
git log --oneline -10 | grep -E '(c64363c|e13a75f|dbfee0b|d835413)' | wc -l
# expect: 4

# Sanity check the v0.1.3 source landed via the shared filesystem.
grep '"version"' package.json src-tauri/tauri.conf.json
grep '^version' src-tauri/Cargo.toml
# expect: all three say 0.1.3
grep -n "setup: loaded flavour" src-tauri/src/lib.rs
# expect: at least one match — that's the success log line added in the lib.rs setup callback
grep -n "_up_/flavours" src-tauri/src/flavour.rs
# expect: matches in both load_flavour and ensure_flavour_in_user_data
grep -n "cp -r deb-payload/usr/lib/sensorium /app/lib/sensorium" packaging/flatpak/app.koher.sensorium.yml
# expect: at least one match — that's the manifest fix

# Confirm prior-host artefacts are present and untouched.
ls -la \
  releases/macos-aarch64/sensorium_0.1.3_aarch64.dmg \
  releases/macos-x64/sensorium_0.1.3_x64.dmg \
  releases/linux-amd64/sensorium_0.1.3_amd64.deb \
  releases/linux-amd64/sensorium-0.1.3-amd64.flatpak
# expect: four files present. If any is missing, STOP — something has eaten the
#   shared state and the build should not proceed until reconciliation.

# 3. Clean only the Rust build cache + flatpak workspace (NOT releases/, NOT .git/).
rm -rf src-tauri/target/release dist .flatpak-builder

# 4. Restore the Linux Tauri CLI native binding. The shared node_modules/
#    currently carries the Mac's darwin-arm64 binding from the prior Mac build;
#    swap it for the linux-arm64 one. This will require the Mac to re-run
#    `npm install` before its next build session (known cross-platform trap).
rm -rf node_modules package-lock.json
npm install
ls node_modules/@tauri-apps/cli-linux-arm64-gnu >/dev/null && echo "linux-arm64 binding OK"

# 5. Sync the canonical Koher UI CSS into src/assets/.
bash scripts/sync-koher-ui.sh

# 6. Build the .deb. Build time ~6 min from cold cache (the rm in step 3 nuked
#    the target/release cache), ~2 min warm.
./node_modules/.bin/tauri build --bundles deb

# 7. Build the .flatpak. The script auto-detects arch from
#    `dpkg --print-architecture` and produces sensorium-0.1.3-arm64.flatpak.
#    Build time ~25 s if Rust cache is warm from step 6.
bash scripts/build-flatpak.sh

# 8. Stage both artefacts in releases/linux-arm64/.
cp src-tauri/target/release/bundle/deb/sensorium_0.1.3_arm64.deb releases/linux-arm64/
cp dist/sensorium-0.1.3-arm64.flatpak releases/linux-arm64/

# 9. Compute SHA-256.
sha256sum \
  releases/linux-arm64/sensorium_0.1.3_arm64.deb \
  releases/linux-arm64/sensorium-0.1.3-arm64.flatpak

# 10. Commit only. Do NOT push.
#     Since .git/ is shared with Mac, this commit advances the shared v0.1.3
#     branch directly — Mac will see it at HEAD without any sync step. Per the
#     Release Artefact Push Discipline rule in tools-scratch/CLAUDE.md (binding
#     9 May 2026): commits adding/modifying .dmg/.deb/.flatpak under releases/
#     must NOT be pushed without an explicit user "release"/"ship" instruction.
git add \
  releases/linux-arm64/sensorium_0.1.3_arm64.deb \
  releases/linux-arm64/sensorium-0.1.3-arm64.flatpak

# Quick check that only artefacts are staged for this commit.
git diff --cached --name-only
# expect: exactly the two paths above.

git commit -m "release(linux-arm64): sensorium 0.1.3 arm64 .deb + arm64 .flatpak (build-only, local-only, not released)"
# DO NOT git push.
```

## Smoke test — primary verification of the v0.1.3 lib.rs + flavour.rs + flatpak-manifest fixes on arm64

The flatpak smoke test on this VM is a **structurally-identical second verification** that the v0.1.3 fixes work on a user machine. The amd64 sandboxed smoke test on the x86_64 Linux dev box (21 May 2026 afternoon) already verified the same code paths; this arm64 run is belt-and-braces. Reasoning is the same as for amd64:

1. The Parallels arm64 VM is not the build machine in any way that breaks the cleanroom — `env!("CARGO_MANIFEST_DIR")` baked into the binary at build time on this VM points at `/media/psf/Dropbox/...`. That path may or may not exist inside the flatpak sandbox depending on Parallels' mount visibility; in practice it does not, but the sandbox's filesystem isolation is what matters, not the macro value.
2. The flatpak sandbox is the cleanroom: the sandboxed binary cannot reach the host's source-tree paths, so the compile-time-manifest fallback (path 4 inside `flavour::load_flavour`) cannot fire. Only the proper user-data + bundle-resource paths are available — which is exactly the user-machine condition.

```bash
# Clear any prior install + user-data to force fresh first-run state.
flatpak uninstall --user app.koher.sensorium -y 2>/dev/null
rm -rf ~/.var/app/app.koher.sensorium/

# Install the freshly-built bundle.
flatpak install --user --bundle releases/linux-arm64/sensorium-0.1.3-arm64.flatpak -y

# Launch with structured logging to catch the success / failure signal.
RUST_LOG=info flatpak run app.koher.sensorium > /tmp/sensorium-smoke-arm64.log 2>&1 &
sleep 8

# Look for the success signal in the log.
grep -E "setup: loaded flavour|setup: ensure_flavour_in_user_data failed|setup: load_flavour failed" /tmp/sensorium-smoke-arm64.log
# success looks like:
#   INFO sensorium_lib: setup: loaded flavour 'sycophancy' v0.1

#   WARN  setup: ensure_flavour_in_user_data failed: ...
```

## What NOT to do

- **Do not `git reset --hard origin/v0.1.3`.** Would erase Mac's `e13a75f` macos-artefacts commit from the shared branch.
- **Do not `git clean -fd`.** Would wipe the staged Mac DMGs and Linux amd64 artefacts from the shared filesystem. Both are needed for the eventual release.
- **Do not push to GitHub.** No `git push`. The release happens later from Mac after explicit user authorisation.
- **Do not cut a GitHub Release.** Build-only today; `gh release create` is forbidden in this session.
- **Do not release-tag the commit.** No `git tag v0.1.3`. The tag belongs to the source commit `d835413` after the user authorises release, set from Mac.
- **Do not delete prior session's artefacts.** v0.1.2 and v0.1.1 arm64 artefacts in `releases/linux-arm64/` should stay where they are — the new ones go in beside them.
- **Do not `git add -A` or `git add .`** — stage the two arm64 artefact paths explicitly to keep this commit clean.

## Failure modes

- **The four expected commits (`c64363c`, `e13a75f`, `dbfee0b`, `d835413`) are not all present in branch history** — the shared filesystem state has drifted. Either (a) the Mac hasn't completed both its artefact commits yet (check on Mac); (b) some other host modified the shared branch; (c) the `.git/` Dropbox-sync corrupted refs. Run `git fetch . && git log --all --oneline -15` and stop until reconciled. Do not build until all four commits are accounted for in the branch history.
- **One of the prior-host artefacts is missing** — Dropbox sync hasn't completed (likely for Linux amd64) or someone ran a `clean` operation. Wait for Dropbox sync, or restore from the Linux box. Do not proceed with the arm64 build until all four prior-host artefacts are present (the eventual `gh release create` needs all six attached together).
- **`./node_modules/.bin/tauri: not found` after npm install** — the cli-linux-arm64-gnu binding didn't install. Inspect with `ls node_modules/@tauri-apps/`. If only `cli-darwin-*` is there (residual from the Mac build), npm's optional-dependencies bug bit again — rerun `rm -rf node_modules package-lock.json && npm install`.
- **`bash scripts/build-flatpak.sh` fails with `unsupported ARCH 'aarch64'`** — the case statement in the script wasn't updated to include both Debian and Linux kernel arch strings. Should not happen with the current script (it uses `dpkg --print-architecture` which returns `arm64`, not `aarch64`). If it does, override with `ARCH=arm64 bash scripts/build-flatpak.sh`.
- **flatpak-builder stalls or fails on a runtime download** — re-confirm `flatpak list --user --runtime` shows both `org.gnome.Platform//49` and `org.gnome.Sdk//49`. If missing, install per `V0.1.2-ARM64-PREREQ.md`.
- **Smoke-test calibration fails with "no flavour loaded"** — one of the three load-path fixes is not in the built binary or the bundled flatpak. Confirm `git log --oneline -5` shows the v0.1.3 source commit `d835413` in history. If it does, check the three grep sanity-checks from step 2 actually returned matches (the source files are present). Capture full Sensorium logs (`/tmp/sensorium-smoke-arm64.log` from the smoke-test block above) and report. If `cp -r deb-payload/usr/lib/sensorium /app/lib/sensorium` is in the flatpak manifest but the file is still missing inside the bundle, inspect with `find /home/$USER/.local/share/flatpak/app/app.koher.sensorium/ -name sycophancy.json` after install — empty result means the manifest's path-resolution is wrong on arm64 (extraction layout may differ); the .deb's content is `dpkg -c releases/linux-arm64/sensorium_0.1.3_arm64.deb | grep sycophancy`.
- **Out of disk** — `src-tauri/target/` Rust build cache and `.flatpak-builder/` can be large; if disk is tight, the cleanup at step 3 helps. The Rust dependency cache rebuild adds ~5-10 minutes but is a one-time cost.
- **`Could not read <sha>` during git operations** — `.git/` is shared via Parallels Shared Folder; in theory no Dropbox-sync corruption applies, but if it does happen, the safest move is to `git fetch origin --force --prune` (does not destroy local state) and retry. Do not `git reset --hard` or `git clean -fd` — they would clobber the prior-host commits + artefacts.
