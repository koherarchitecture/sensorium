# V0.1.2-ARM64-BUILD — build the arm64 .deb and arm64 .flatpak

For the Claude Code session running on the **arm64 Parallels VM** (Apple Silicon Linux). Builds the v0.1.2 arm64 artefacts and stages them in `releases/linux-arm64/`. **Build only — no release.** The artefacts sit ready for when the v0.1.2 ship window opens.

The marquee deliverable for v0.1.2 is the **arm64 `.flatpak`** — closing the parity gap that v0.1.0 and v0.1.1 both deferred. This brief verifies the arm-aware build pipeline (committed on `v0.1.2` branch as `b7a4779`) actually produces a valid bundle end-to-end.

## Prerequisites

The arm64 GNOME runtimes (`org.gnome.Platform//49` + `org.gnome.Sdk//49` for aarch64) must be installed. Per the 9 May 2026 confirmation in `releases/V0.1.2-ARM64-PREREQ.md`, they already are on this VM — `flatpak list --user --runtime` should show both. If not, run that prereq brief first.

## Path

The repo lives at **`/media/psf/Dropbox/personal_projects/koher/tools-scratch/02-sensorium/sensorium/`** (Parallels Shared Folder mount, not `~/Dropbox/`).

## Steps

```bash
# 1. Confirm host.
uname -s -m
# expect: Linux aarch64

# 2. Move to the repo and align with origin/v0.1.2.
cd /media/psf/Dropbox/personal_projects/koher/tools-scratch/02-sensorium/sensorium
pkill -f tauri 2>/dev/null
pkill -f flatpak-builder 2>/dev/null
rm -rf src-tauri/target/release dist .flatpak-builder
git fetch origin --force --prune
git checkout v0.1.2
git reset --hard origin/v0.1.2
git clean -fd
git config user.name "Koher Architecture"
git config user.email "hello@koher.app"

# Confirm version bump landed.
grep '"version"' package.json src-tauri/tauri.conf.json
grep '^version' src-tauri/Cargo.toml
# expect: all three say 0.1.2

# 3. Restore the Linux Tauri CLI native binding (Dropbox-synced
#    node_modules carries the wrong platform's binding by default).
rm -rf node_modules package-lock.json
npm install

# 4. Build the .deb.
./node_modules/.bin/tauri build --bundles deb

# 5. Build the .flatpak. The script auto-detects arch from
#    `dpkg --print-architecture` and produces sensorium-0.1.2-arm64.flatpak.
bash scripts/build-flatpak.sh

# 6. Stage both artefacts in releases/linux-arm64/.
cp src-tauri/target/release/bundle/deb/sensorium_0.1.2_arm64.deb releases/linux-arm64/
cp dist/sensorium-0.1.2-arm64.flatpak releases/linux-arm64/

# 7. Compute SHA-256.
shasum -a 256 \
  releases/linux-arm64/sensorium_0.1.2_arm64.deb \
  releases/linux-arm64/sensorium-0.1.2-arm64.flatpak

# 8. Commit. Push will likely fail on this host (no GitHub auth);
#    the local commit is enough — Mac picks it up via Dropbox-synced
#    .git and pushes from there. Per the auth-gap caveat in
#    releases/README.md.
git add releases/linux-arm64/
git commit -m "release(linux-arm64): sensorium 0.1.2 arm64 .deb + arm64 .flatpak (build-only, not released)"
git push 2>&1 || echo "push failed (expected — auth gap); Mac will push"
```

## Smoke test (optional but recommended)

Before declaring success, verify the .flatpak actually installs and runs on this VM:

```bash
flatpak install --user --bundle releases/linux-arm64/sensorium-0.1.2-arm64.flatpak -y
flatpak run app.koher.sensorium &
sleep 4
pkill -f sensorium-flatpak 2>/dev/null
flatpak uninstall --user app.koher.sensorium -y
```

If the app launches without error and the window appears, the arm64 flatpak parity is verified. If it errors, capture the message and report.

## What NOT to do

- **Do not cut a GitHub Release.** Build-only today; `gh release create` is forbidden in this session. The release happens later from the Mac.
- **Do not release-tag the commit.** No `git tag v0.1.2`. The tag belongs to the release commit on `main` after merge, not to a build-only commit on the branch.
- **Do not delete the prior session's artefacts.** `releases/linux-arm64/sensorium_0.1.1_arm64.deb` should stay where it is — it's the v0.1.1 record. The new artefacts go in beside it.

## Failure modes

- **`./node_modules/.bin/tauri: not found` after npm install** — the cli-linux-arm64 binding didn't install. Inspect with `ls node_modules/@tauri-apps/`. If only `cli-darwin-*` is there, npm's optional-dependencies bug bit again — rerun `rm -rf node_modules package-lock.json && npm install`.
- **`bash scripts/build-flatpak.sh` fails with `unsupported ARCH 'aarch64'`** — would mean the case statement in the script wasn't updated to include both Debian and Linux kernel arch strings. Should not happen with the current script (it uses `dpkg --print-architecture` which returns `arm64`, not `aarch64`). If it does, override with `ARCH=arm64 bash scripts/build-flatpak.sh`.
- **flatpak-builder stalls or fails on a runtime download** — re-confirm `flatpak list --user --runtime` shows both `org.gnome.Platform//49` and `org.gnome.Sdk//49`. If missing, install per `V0.1.2-ARM64-PREREQ.md`.
- **Out of disk** — `src-tauri/target/` Rust build cache and `.flatpak-builder/` can be large; if disk is tight, the recovery cleanup at step 2 helps. The Rust dependency cache rebuild adds ~5-10 minutes but is a one-time cost.
