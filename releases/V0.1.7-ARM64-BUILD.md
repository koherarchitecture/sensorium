## Prerequisites

- GNOME runtimes for arm64 flatpak (one-time): `flatpak install --user flathub org.gnome.Platform//49 org.gnome.Sdk//49`. See `releases/README.md` Step 3.
- Tauri CLI Linux arm64 binding present in `node_modules/@tauri-apps/cli-linux-arm64-gnu/`. If `npm install` ever produced the wrong binding from a different host's session (Dropbox-synced `node_modules` cross-platform trap), nuke and reinstall.

## Path

The repo lives at `~/Dropbox/personal_projects/koher/tools-release/sensorium/` (the VM mounts the Mac's Dropbox share at `/media/psf/Dropbox/...` per the `reference_parallels_shared_folder_constraints` memory).

## Steps

```bash
# 1. Confirm host.
uname -s -m
# expect: Linux aarch64

# 2. Move to the repo, align with origin/v0.1.7, cross-platform npm reset.
cd ~/Dropbox/personal_projects/koher/tools-release/sensorium
pkill -f tauri 2>/dev/null
git fetch origin --force --prune --tags
git checkout v0.1.7
git reset --hard origin/v0.1.7

# Confirm the source state — expect HEAD at 6b08535 (test fix) or later.
git log --oneline -3

# Confirm version bumps.
grep '"version"' package.json src-tauri/tauri.conf.json
grep '^version' src-tauri/Cargo.toml
# expect: 0.1.7 across all three

# Optional sanity-check the test suite — expect 38/38 pass.
( cd src-tauri && cargo test --lib --quiet 2>&1 | tail -3 )

# 3. Cross-platform node_modules reset — Dropbox-synced node_modules can
#    carry the wrong native binding from a Mac or amd64-Linux session.
rm -rf node_modules package-lock.json
npm install
ls node_modules/@tauri-apps/cli-linux-arm64-gnu >/dev/null && echo "linux arm64 binding OK"

# 4. Sync the canonical Koher UI CSS.
bash scripts/sync-koher-ui.sh

# 5. Build the arm64 .deb.
./node_modules/.bin/tauri build --bundles deb

# 6. Build the arm64 .flatpak.
bash scripts/build-flatpak.sh

# 7. Stage both artefacts.
cp src-tauri/target/release/bundle/deb/sensorium_0.1.7_arm64.deb releases/linux-arm64/
cp dist/sensorium-0.1.7-arm64.flatpak releases/linux-arm64/

# 8. Compute SHA-256 for BUILD-STATUS.
sha256sum \
  releases/linux-arm64/sensorium_0.1.7_arm64.deb \
  releases/linux-arm64/sensorium-0.1.7-arm64.flatpak

# 9. Commit only. Do NOT push.
git add releases/linux-arm64/sensorium_0.1.7_arm64.deb releases/linux-arm64/sensorium-0.1.7-arm64.flatpak
git commit -m "release(linux-arm64): sensorium 0.1.7 arm64 .deb + arm64 .flatpak (build-only, local-only, not released)"
# Skip git push.
```

## Smoke-test

Sandboxed flatpak is the cleanroom that exposes load-path bugs the source-tree build cannot. After install:

```bash
flatpak install --user releases/linux-arm64/sensorium-0.1.7-arm64.flatpak --reinstall -y
flatpak run --env=RUST_LOG=info app.koher.sensorium 2>&1 | head -30
# expect to see (among other startup lines):
#   INFO sensorium_lib: Sensorium starting up
#   INFO sensorium_lib::settings: no preferences file at ... — using defaults
#   INFO sensorium_lib: setup: loaded flavour 'sycophancy' v0.1
#
# The "loaded flavour" line IS the signal that the new split_ratio_mapping
# field in sycophancy.json deserialised cleanly under the v0.1.7 schema —
# if the field were malformed or the schema rejected it, FlavourConfig
# deserialisation would fail and you would see a "load_flavour failed"
# error line instead.
```

If the wizard launches and shows 4 steps with the third being "Set your target ratio", the v0.1.7 critical-path is verified. Confirm the slider lands at 7:3 by default and that the Settings → Publish artefact button opens the self-rated badge entry modal.
