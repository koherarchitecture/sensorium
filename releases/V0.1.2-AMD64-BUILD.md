# V0.1.2-AMD64-BUILD — build the amd64 .deb and amd64 .flatpak

For the Claude Code session running on the **x86_64 Linux dev box**. Builds the v0.1.2 amd64 artefacts and stages them in `releases/linux-amd64/`. **Build only — no release.** The artefacts sit ready for when the v0.1.2 ship window opens.

## Prerequisites

- `flatpak`, `flatpak-builder`, `jq`, `dpkg` installed (already present from the v0.1.0 / v0.1.1 build sessions per `BUILD-STATUS.md`).
- The amd64 GNOME runtimes (`org.gnome.Platform//49` + `org.gnome.Sdk//49` for amd64) installed on this host. Confirm with `flatpak list --user --runtime`. If absent: `flatpak install --user flathub org.gnome.Platform//49 org.gnome.Sdk//49`.
- GitHub auth status irrelevant — this brief does not push regardless. See the **Release Artefact Push Discipline** rule in `tools-scratch/CLAUDE.md`.

## Path

The repo lives at `~/Dropbox/personal_projects/koher/tools-scratch/02-sensorium/sensorium/` (Linux-native Dropbox client). Adjust if the local Dropbox mount point differs.

## Steps

```bash
# 1. Confirm host.
uname -s -m
# expect: Linux x86_64

# 2. Move to the repo and align with origin/v0.1.2.
cd ~/Dropbox/personal_projects/koher/tools-scratch/02-sensorium/sensorium
pkill -f tauri 2>/dev/null
pkill -f flatpak-builder 2>/dev/null
rm -rf src-tauri/target/release dist .flatpak-builder
git fetch origin --force --prune
git checkout v0.1.2
git reset --hard origin/v0.1.2
git clean -fd
git config user.name "Koher Architecture"
git config user.email "hello@koher.app"

# Confirm the version bump landed.
grep '"version"' package.json src-tauri/tauri.conf.json
grep '^version' src-tauri/Cargo.toml
# expect: all three say 0.1.2

# 3. Restore the Linux Tauri CLI native binding (Dropbox-synced
#    node_modules carries the wrong platform's binding by default).
rm -rf node_modules package-lock.json
npm install

# 4. Build the .deb.
./node_modules/.bin/tauri build --bundles deb

# 5. Build the .flatpak. The script auto-detects arch from
#    `dpkg --print-architecture` and produces sensorium-0.1.2-amd64.flatpak.
bash scripts/build-flatpak.sh

# 6. Stage both artefacts in releases/linux-amd64/.
cp src-tauri/target/release/bundle/deb/sensorium_0.1.2_amd64.deb releases/linux-amd64/
cp dist/sensorium-0.1.2-amd64.flatpak releases/linux-amd64/

# 7. Compute SHA-256.
shasum -a 256 \
  releases/linux-amd64/sensorium_0.1.2_amd64.deb \
  releases/linux-amd64/sensorium-0.1.2-amd64.flatpak

# 8. Commit only. Do NOT push.
#    Per the Release Artefact Push Discipline rule in tools-scratch/CLAUDE.md
#    (binding 9 May 2026): commits adding/modifying .dmg/.deb/.flatpak under
#    releases/ must NOT be pushed without an explicit user "release"/"ship"
#    instruction. This host has GitHub auth and could push, but the rule binds
#    regardless of auth state. Mac will receive the commit via Dropbox-synced
#    .git and hold it locally too.
git add releases/linux-amd64/
git commit -m "release(linux-amd64): sensorium 0.1.2 amd64 .deb + amd64 .flatpak (build-only, local-only, not released)"
# Skip git push entirely.
```

## What NOT to do

- **Do not push to GitHub.** Per the Release Artefact Push Discipline rule. Even though this host has auth, the rule binds. The release happens later from Mac after explicit user authorisation.
- **Do not cut a GitHub Release.** Build-only today; `gh release create` is forbidden in this session.
- **Do not release-tag the commit.** No `git tag v0.1.2`. The tag belongs to the release commit on `main` after merge, not to a build-only commit on the branch.
- **Do not delete the prior session's artefacts.** `releases/linux-amd64/sensorium_0.1.1_amd64.deb` and `sensorium-0.1.1-amd64.flatpak` should stay where they are — they are the v0.1.1 record. The new artefacts go in beside them.

## Failure modes

- **`./node_modules/.bin/tauri: not found` after npm install** — the cli-linux-x64 binding didn't install. Inspect with `ls node_modules/@tauri-apps/`. If only `cli-darwin-*` is there, npm's optional-dependencies bug bit again — rerun `rm -rf node_modules package-lock.json && npm install`.
- **`bash scripts/build-flatpak.sh` fails on a missing runtime** — re-confirm `flatpak list --user --runtime` shows both `org.gnome.Platform//49` and `org.gnome.Sdk//49` for amd64.
- **flatpak-builder stalls** — typical fix is `rm -rf .flatpak-builder dist/flatpak-build dist/flatpak-repo` and retry. The script's `--force-clean` should handle most cases, but a stale OSTree repo can confuse it.
- **`git checkout v0.1.2` fails** — run `git fetch origin` first. If the branch genuinely doesn't exist remotely, the v0.1.2 work hasn't been pushed from Mac yet — stop and report.
- **`Could not read <sha>` errors during git operations** — the `.git/`-via-Dropbox corruption pattern. Re-run step 2 after a minute (Dropbox sync catching up). Persistent errors mean the local `.git/` is genuinely corrupt — see `releases/RECOVERY.md` for the fresh-clone path.
