# V0.1.7-WINDOWS-BUILD — build the Windows .msi (x86_64)

For the Claude Code session running on a **Windows host (x86_64)**. Builds the v0.1.7 Windows installer and stages it in `releases/windows-x64/`. **Build only — no release.** The artefact sits ready for the v0.1.7 ship window (5 June 2026).

**This is the first Windows build in the Sensorium matrix.** The koher.app/tools/sensorium Upcoming table added the Windows slot at v0.1.6 ship; v0.1.7 is the first cut that produces a Windows artefact. If anything specific to Windows packaging surprises this session, capture it in `releases/V0.1.7-WINDOWS-DONE.md` so the next Windows cut has the lessons.

**Context for v0.1.7:** see `V0.1.7-MAC-BUILD.md` for the full substance list. Same source state across all host briefs.

## Prerequisites

- Rust toolchain with MSVC target: `rustup target add x86_64-pc-windows-msvc` (already default on Windows installs of rustup).
- Visual Studio Build Tools 2022 (or 2019) with C++ build tools workload, including Windows 10/11 SDK.
- WebView2 runtime present (ships with modern Windows; required at runtime, not build time).
- Node.js 20+ LTS.
- WiX Toolset v3.x in PATH (Tauri's MSI bundler requires it). Install via `dotnet tool install --global wix` or use the Chocolatey `wixtoolset` package.
- Tauri CLI Windows binding at `node_modules\@tauri-apps\cli-win32-x64-msvc\`. If `npm install` produced a non-Windows binding from a Dropbox-synced `node_modules`, nuke and reinstall.

## Path

The repo lives at `%USERPROFILE%\Dropbox\personal_projects\koher\tools-release\sensorium\` (Windows-native Dropbox client). Use the cmd / PowerShell path conventions; the brief uses cmd-style commands. Adapt for PowerShell if preferred (path forms are equivalent).

## Steps (cmd shell)

```cmd
:: 1. Confirm host.
ver
:: expect: Microsoft Windows [Version 10/11 ...]

:: 2. Move to the repo and align with v0.1.7 source state.
cd /d %USERPROFILE%\Dropbox\personal_projects\koher\tools-release\sensorium
taskkill /im tauri.exe /f 2>nul
rmdir /s /q src-tauri\target\release\bundle 2>nul
git fetch origin --force --prune
:: If v0.1.7 branch cut: git checkout v0.1.7 && git reset --hard origin/v0.1.7
git config user.name "Koher Architecture"
git config user.email "hello@koher.app"

:: Confirm versions.
findstr "version" package.json src-tauri\tauri.conf.json
findstr "^version" src-tauri\Cargo.toml
:: expect: 0.1.7

:: 3. Cross-platform node_modules reset.
rmdir /s /q node_modules
del package-lock.json
npm install
if not exist node_modules\@tauri-apps\cli-win32-x64-msvc echo MISSING WINDOWS BINDING && exit /b 1

:: 4. Sync the canonical Koher UI CSS. The sync script is bash;
::    run it under Git Bash if available, otherwise copy by hand:
bash scripts\sync-koher-ui.sh
:: If bash unavailable: copy /Y ..\..\ui-system\koher-ui.css src\assets\koher-ui.css

:: 5. Build the Windows .msi (x86_64).
::    Build time ~3-5 min cold, ~1-2 min warm.
node_modules\.bin\tauri build --target x86_64-pc-windows-msvc

:: 6. Stage the artefact.
if not exist releases\windows-x64 mkdir releases\windows-x64
copy /Y src-tauri\target\x86_64-pc-windows-msvc\release\bundle\msi\sensorium_0.1.7_x64_en-US.msi releases\windows-x64\

:: 7. Compute SHA-256.
certutil -hashfile releases\windows-x64\sensorium_0.1.7_x64_en-US.msi SHA256

:: 8. Commit only. Do NOT push.
git add releases\windows-x64\sensorium_0.1.7_x64_en-US.msi
git commit -m "release(windows-x64): sensorium 0.1.7 x64 .msi (build-only, local-only, not released)"
:: Skip git push.
```

## What might surprise on Windows (heads-up)

- **WiX licence dialog**: Tauri's default MSI includes a licence dialog. The licence file path is in `tauri.conf.json` → `bundle.windows.wix.license`. If absent, the MSI may fail to build with a "license file not found" error. Tauri's default behaviour is to skip the dialog if no licence path is configured — current Sensorium config does not set one, so the dialog should be absent.
- **Code signing**: Tauri produces an unsigned MSI. Windows will SmartScreen-warn first-time runners. This is normal for v0.1.x; signing infrastructure is a v0.2 concern.
- **`scripts/sync-koher-ui.sh`** is bash-only. Use Git Bash, or copy the file by hand. The script's logic is trivial (`cp ../../ui-system/koher-ui.css src/assets/koher-ui.css`).
- **Path length limits**: Windows historically caps paths at 260 chars. Tauri's `target/x86_64-pc-windows-msvc/release/bundle/...` paths can flirt with this on deeply-nested repo locations. If a build fails with `path too long`, move the repo closer to the drive root.
