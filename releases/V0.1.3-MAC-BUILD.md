# V0.1.3-MAC-BUILD — build the macOS aarch64 .dmg and x64 .dmg

For the Claude Code session running on the **Mac dev box (Apple Silicon)**. Builds the v0.1.3 macOS artefacts and stages them in `releases/macos-aarch64/` and `releases/macos-x64/`. **Build only — no release.** The artefacts sit ready for the v0.1.3 ship window (target tonight, 21 May 2026 (after Mac + arm64 builds complete)).

**Context for v0.1.3:** Release combining four calibration-load fixes + one new feature, overriding the two-week cadence floor (originally planned as `v0.1.2.1` hotfix; SemVer rejected the four-dot string; suggested-tone icons feature pulled forward from the originally-planned 5 June v0.1.3). Substance: (a) `src-tauri/src/lib.rs` moves flavour seed-and-load into the setup callback with real paths via `handle.path()` — load-bearing fix for the "no flavour loaded" calibration error; (b) `src-tauri/src/flavour.rs` checks `_up_/flavours/` first in both `load_flavour` and `ensure_flavour_in_user_data` (Tauri's bundler prefixes `../`-relative resources with `_up_/`); (c) `src/js/first-run.js` adds defence-in-depth wizard-time seed; (d) `src/js/settings-modal.js` wires the three dead install-flavour buttons to an inline notice; (e) suggested-tone cues above the composer — Rust derivation in `src-tauri/src/rules/tone_suggestions.rs`, non-interactive (system-selected coaching cues), 5-candidate vocabulary. Mac DMGs ship alongside amd64 Linux (already built + smoke-tested 21 May afternoon) and arm64 Linux artefacts.

## Prerequisites

- Both Rust targets installed: `aarch64-apple-darwin` (default on Apple Silicon) and `x86_64-apple-darwin` (cross-compile target for Intel Macs). Confirm with `rustup target list --installed`. If `x86_64-apple-darwin` is missing: `rustup target add x86_64-apple-darwin`.
- The Tauri CLI darwin binding present at `node_modules/@tauri-apps/cli-darwin-arm64/`. If `npm install` ever produced a Linux binding (Dropbox-synced `node_modules` from a prior Linux build can cause this), nuke and reinstall: `rm -rf node_modules package-lock.json && npm install`.
- `~/.local/bin/cc` shadow workaround: builds may need `PATH="/usr/bin:$PATH"` prefix to avoid a `cc` from `~/.local/bin/` interfering with Apple's clang. The `PATH` override below is preserved from the v0.1.2 Mac build for safety.
- GitHub auth status irrelevant — this brief does not push regardless. See the **Release Artefact Push Discipline** rule in `tools-scratch/CLAUDE.md`.

## Steps

```bash
# 1. Confirm host.
uname -s -m
# expect: Darwin arm64

# 2. Move to the repo and align with origin/v0.1.3.
cd ~/Dropbox/personal_projects/koher/tools-release/sensorium
pkill -f tauri 2>/dev/null
rm -rf src-tauri/target/aarch64-apple-darwin/release src-tauri/target/x86_64-apple-darwin/release dist
git fetch origin --force --prune
git checkout v0.1.3
git reset --hard origin/v0.1.3
git clean -fd
git config user.name "Koher Architecture"
git config user.email "hello@koher.app"

# Confirm the version bump landed.
grep '"version"' package.json src-tauri/tauri.conf.json
grep '^version' src-tauri/Cargo.toml
# expect: all three say 0.1.3

# 3. Restore the darwin Tauri CLI native binding.
#    Dropbox-synced node_modules from a Linux build will carry the wrong
#    platform's binding; force a fresh install so the cli-darwin-arm64
#    package lands.
rm -rf node_modules package-lock.json
npm install
ls node_modules/@tauri-apps/cli-darwin-arm64 >/dev/null && echo "darwin binding OK"

# 4. Sync the canonical Koher UI CSS into src/assets/.
bash scripts/sync-koher-ui.sh

# 5. Build the aarch64 (Apple Silicon) .dmg.
#    PATH override avoids the ~/.local/bin/cc shadow that can interfere
#    with Apple clang. Build time ~2 min from a warm cache.
PATH="/usr/bin:$PATH" ./node_modules/.bin/tauri build --target aarch64-apple-darwin

# 6. Build the x86_64 (Intel) .dmg.
#    Cross-compile target. Build time ~1 min 40 s from a warm cache.
PATH="/usr/bin:$PATH" ./node_modules/.bin/tauri build --target x86_64-apple-darwin

# 7. Stage both artefacts.
cp src-tauri/target/aarch64-apple-darwin/release/bundle/dmg/sensorium_0.1.3_aarch64.dmg releases/macos-aarch64/
cp src-tauri/target/x86_64-apple-darwin/release/bundle/dmg/sensorium_0.1.3_x64.dmg releases/macos-x64/

# 8. Compute SHA-256.
shasum -a 256 \
  releases/macos-aarch64/sensorium_0.1.3_aarch64.dmg \
  releases/macos-x64/sensorium_0.1.3_x64.dmg

# 9. Commit only. Do NOT push.
#    Per the Release Artefact Push Discipline rule in tools-scratch/CLAUDE.md
#    (binding 9 May 2026): commits adding/modifying .dmg/.deb/.flatpak under
#    releases/ must NOT be pushed without an explicit user "release"/"ship"
#    instruction. This host has GitHub auth and could push, but the rule binds
#    regardless of auth state.
git add releases/macos-aarch64/ releases/macos-x64/
git commit -m "release(macos): sensorium 0.1.3 aarch64 .dmg + x64 .dmg (build-only, local-only, not released)"
# Skip git push entirely.
```

## Failure modes

- **`./node_modules/.bin/tauri: not found` after npm install** — the cli-darwin-arm64 binding didn't install. Inspect with `ls node_modules/@tauri-apps/`. If only `cli-linux-*` is there, npm's optional-dependencies bug bit again — rerun `rm -rf node_modules package-lock.json && npm install`.
- **`error: linker cc not found` or `cc: command not found`** — the `~/.local/bin/cc` shadow is masking Apple's compiler. Confirm the `PATH="/usr/bin:$PATH"` prefix is in place; without it, `cc` resolves to the wrong binary. Verify with `which cc` after the override.
- **`error: could not find or load Xcode CLT`** — Xcode Command Line Tools missing; install with `xcode-select --install`. This shouldn't happen on a working dev box but recovers cleanly if it does.
- **`error[E0463]: can't find crate for 'std'` for x86_64-apple-darwin** — the cross-compile target isn't installed. `rustup target add x86_64-apple-darwin` then retry step 6.
- **`git checkout v0.1.3` fails** — run `git fetch origin` first. If the branch genuinely doesn't exist remotely yet, the v0.1.3 work hasn't been pushed yet — stop and report.
- **`Could not read <sha>` errors during git operations** — the `.git/`-via-Dropbox corruption pattern. Re-run step 2 after a minute (Dropbox sync catching up). Persistent errors mean the local `.git/` is genuinely corrupt — see `releases/RECOVERY.md` for the fresh-clone path.
